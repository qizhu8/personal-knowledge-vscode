## Shared PUBLIC COPY-and-RETAIN: precise missing proof

Current typed legacy reading checks public privacy scope, checked area paths,
safe ownership/modes, single-link regular files and byte/identity CAS.
It does **not** require an exclusive Markdown referrer to read a public file.
The actual fresh public move approval remains required by the write adapter.
No additional human read grant requirement was found for a checked public
source in that path.

The concrete blocker is instead the existing **deletion-oriented move intent**:

* planning calls `assertLegacyAssetsUnshared`;
* copies have no retained-source disposition;
* completion removes every legacy source;
* final recovery requires those sources to be absent.

Supporting original public sharing would need a separately designed typed
`retain` versus `remove` disposition and reference/CAS/provenance proof:
retained shared source bytes/identity remain checked in every recovery phase,
no unlink/rewrite of retained sources/referrers occurs, new paired copies are
independently owned, and final/receipt/B1 conditions describe retention.
That is an unimplemented effect/proof boundary, not “shared means unreadable.”
Additional consent disclosure and actual qualification remain parent decisions.
This leaf neither implements nor promotes that next boundary.

Private source publication is different: existing privacy denial prevents
copying those bytes to a public pair. Ordinary move approval is not a private
publication/declassification grant.
