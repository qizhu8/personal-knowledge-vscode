## API composition and read/restore rules

The guarded API/Task adapter:

1. Routes only the exact independently validated source candidate to
   `prepareAdoption`, not every metadata Session.
2. Uses `preparedSelection` / `preparedModelSelectionId` from the real branded
   preparation; the native selection preceded adoption/send review.
3. Uses existing `start/bind/execution/finish` and the singleton executor.
4. Preserves source namespace/UUID and imports original dialogue/tool references
   as historical/untrusted context; do not silently omit old terminal evidence.
   `NativeManagedTaskAttempt.historicalMessageIds` identifies the actual imported
   history, not an execution token.
5. Keeps all other managed/worker/uncertain cases gated, including a failed
   adoption’s unknown commit until actual receipt reconciliation.

The producer validates its actual pending resolved request/current selection,
epoch, source and old Goal/input/context binding. It serializes review, retires
denied/cancelled/stale requests, and requires the distinct native affirmative
button. Generic “Allow this native model request” is not adoption approval.
Send consent is separately bound to the reviewed command/argument digest and
expiry. The host imports only the adoption port type and dynamically loads the
unchanged validators from the verified installed payload: no static Core Goal
evaluator or second Goal engine is bundled into the native host.

Original source reads stay `archive_only`; copied metadata does not become
ownership. Current native authority requires the actual scoped same-Core
capability. Read-only archived B1 receipt data is historical provenance, not a
restored grant. Fresh disjoint B0 must restore unchanged original bytes and must
not inherit the native database, mappings, approvals or attempts. The bounded positive installed adoption/B1/B0 proof has now passed. Broader
