## Library Recipe contract

Python `recipe_create_from_skill` invokes the shipped TypeScript compiler through
`recipe_compiler_bridge.js`. MCP generation supplies the actual Node/Electron
executable and extension contracts path; Electron runs with `ELECTRON_RUN_AS_NODE`.
Missing, failed, timed-out or invalid compilation fails closed—there is no Python
normalization substitute or raw-hash fallback. Recipe MCP capability **1.8.2**
causes older installed components to be regenerated by normal MCP maintenance.

Both legacy and filesystem authoring save `compiled.model` and
`compiled.executableDigest`. `source_skill_node_id` identifies the binding explicitly;
when omitted, the original input's first node is captured **before** compilation.
Filesystem discovery checks the same compiler digest. Existing TS create/update/
import paths already compile; import and migration integrity checks stay strict.
Instance-only adhoc run identities are not Library Recipe exports and retain their
existing definition-plus-bindings runtime fingerprint.

### Existing legacy raw-digest Recipes

Sync export deliberately does **not** change a Recipe's digest or revision.
Local Recipe failures route to the real Recipe browser editor, not a fabricated
`recipes/...json` source file. The durable issue includes the actual legacy
`projects.json` locator, `/payload/state/recipes`, and Recipe identity.

For a successfully compiling definition whose stored digest is demonstrably the
raw-definition canonical hash:

1. **Preview Recipe recompile** compares the original record with the exact
   supported `updateRecipe` result, including the next revision and compiled model.
2. **Approve recompile** requires a prior preview and explicit modal approval.
   Store-version and full-record digest checks reject stale reviews.
3. Known pinned Library Recipe definitions/methodology and persisted run child
   definitions block recompile. Consumers must be reviewed/updated explicitly;
   no pin is silently retargeted. Frozen runs themselves remain byte-for-byte
   unchanged and continue to carry their original revision/digest.
4. Apply invalidates the content catalog but does not Sync or push.
   **Revalidate & Sync** rebuilds current content and resumes the normal guarded flow.

Arbitrary digest corruption, invalid definitions and System Recipes are not
eligible for this conservative repair. External pins are not rewritten; they
require explicit requalification. Invalid filesystem Recipe records continue
to use the existing Recipe diagnostics path rather than being admitted to the
Library or silently migrated. Repair supported legacy records before migrating
them to the filesystem store.

## Local content preflight

Preflight collects marker, Recipe digest/definition, frontmatter and materialization
errors without abandoning previously found issues. Individual dependency and
directory-member read errors do not hide inspectable siblings. Path collisions
remain blockers, and Local ignore/System exclusions remain in force.

`GitHubSyncContentRepairError` remains the typed, non-retryable attention boundary
across daemon RPC and durable persistence. Each issue retains its reason, original
diagnostics/error, source locator and content digest. Marker repair candidates are
not offered for Recipe digest errors. Marker actions retain their existing
approval, unsaved-editor, root/symlink and concurrent-write checks; new records
also guard the original source-byte hash, including line-ending-only edits.

The UI reports **Needs attention: local content validation** and clearly states
that this attempt has not fetched Remote and has no Base/Remote repair candidates.
It does not label these blockers “Fetch / Pull failed” or invent a three-way
conflict. Attention neither pauses Auto nor consumes its network retry budget.
All final candidate, staged-blob, manifest and concurrent-Remote checks remain.

## Historical Base line endings

Historical Base blob hashes are now verified. A mismatch is compatible only if
valid, non-NUL UTF-8 bytes reproduce the exact manifest hash under a uniform
LF/CRLF conversion. Its trusted comparison digest is LF; arbitrary mismatches,
invalid UTF-8, missing blobs and non-line-ending changes still fail.

Original manifest/blob/comparison hashes, paths and historical commit identity
are retained in the target's managed checkout-state `base-integrity/<hash>.json`
evidence (outside synchronized knowledge). Past Git commits and `lastSync` are
not rewritten. Latest Remote still uses byte-strict manifest/blob validation and
cannot take this compatibility exception.
