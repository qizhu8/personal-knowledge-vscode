## Bounded actual installed cases

`installedNativeManagedTaskAdoptionUiStages` exports eight exact stages:

1. `native-task-adoption-source`: independent signed source-only approval and
   archive reads. Before adoption the original Session is `archive_only`, with
   no canonical Chat/Goal/map/attempt.
2. `native-task-adoption-deny-review`: explicit adoption **Deny**. No canonical
   state or provider call may be published.
3. `native-task-adoption-deny-send`: approve the distinct
   **Adopt this exact goal and reset acceptance** modal, then separately deny
   send. Adoption consent alone still creates no canonical state/provider call.
4. `native-task-adoption-positive`: preserve the same original identities and
   full objective; first inspect the actual current Task, then deliberately
   attempt an old-evidence-only resolution. The Core must refuse it. A genuine
   current Note read, Task Harness report, validation start/outcome and fresh
   `report_work` are required before resolution. Seven real tool proposals
   run through exact record review/effect approval; an eighth, tool-free
   hard-limit summary completes the response. Task stays `active` and
   `taskCompletion: not-claimed`, not human-accepted.
5. `native-task-adoption-replay`: the reused command receives its **own actual
   public approval** but no new inference, import or attempt.
6. `native-task-adoption-collision`: while the actual original adoption review
   is pending, a fixture operator uses real canonical create + append/CAS
   operations to reserve the same UUID with a newer input. Only after that
   commit does the observer click the **same captured modal/button**. Adoption
   must publish no map/Task/attempt/native execution and must preserve the newer
   input. That source Session remains `archive_only`; matching a generic Core
   UUID is not native adoption authority. This is the initial-import ownership
   boundary, distinct from the already-qualified fresh-Task inference race.
7. `native-task-adoption-source-revoke`: actual independent source revocation,
   host still live; subsequent work must fail before any new request/effect.
8. `native-task-adoption-complete`.

Expected actual registered provider calls: **8**. Denials/collision/revocation
must never reach it. Expected adopted Tasks/attempts: **1 / 1**. The collision’s
separate fixture-operator Chat/input is preserved but never counted as adoption.

The observer uses actual rendered DOM, exact normalized titles and structured
source/profile/Goal/request/model/context/argument/plan pins. It rejects another
Root or an identical-text replacement modal. It is not a generic approval loop.
Each inference and Core tool review/effect still gets its own choice.
